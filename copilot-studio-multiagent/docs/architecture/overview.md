# AIエージェント組織システム 全体設計ドキュメント
## Microsoft Copilot Studio × Power Platform 実装版

---

## 1. システム概要

### 設計思想
シリコンバレー型の組織運営モデルをAIエージェントアーキテクチャに適用する。  
1つのAIにすべての文脈を渡すことで発生するハルシネーションと出力ブレを防ぐため、  
**18体の専門エージェント**による役割分担型マルチエージェントシステムを構築する。

### 4つの設計原則
1. **専門化（Specialist）** — 各エージェントは自身の限定領域にのみ責任を持つ
2. **多重レビュー（Review）** — 重要アウトプットは複数エージェントを通して品質担保
3. **非同期引き継ぎ（Handoff）** — エージェント同士は直接会話せず、ファイル経由で連携
4. **裁量の明示（Authority）** — AIが自己判断してよい範囲と人間へのエスカレーション境界を明文化

## 3. Microsoftサービス対応マッピング

| 元設計（動画） | Microsoft実装 | 用途 |
|---|---|---|
| Obsidian /Context/ | SharePoint /Context/ ライブラリ | 哲学・ブランドルール・環境定義 |
| Obsidian /Inbox/ | SharePoint /Inbox/ ＋ Teams Inboxチャンネル | CEO入力受信口 |
| Obsidian /AI Handoff/ | SharePoint /AI-Handoff/ ライブラリ | エージェント間引き継ぎ書 |
| Kanban Board | Microsoft Planner | タスク管理・アサイン・進捗 |
| AIエージェント（18体） | Copilot Studio エージェント | 各専門エージェント |
| エージェント間オーケストレーション | Copilot Studio マルチエージェント連携 | 親→子エージェント呼び出し |
| 夜間自動ワークフロー | Power Automate スケジュールフロー | 定時トリガー自律実行 |
| モーニングスタンドアップ | Power Automate → Teams通知 | 朝の進捗サマリー自動送信 |
| LLM（Claude Opus等） | Azure OpenAI（GPT-4o / GPT-4o-mini） | Copilot Studio経由で呼び出し |
| Local AI（Ollama） | Power Automate（定型処理フロー） | クリーンアップ等の軽量タスク |

## 6. リスクと対策

| リスク | 内容 | Microsoft実装での対策 |
|---|---|---|
| 静かな崩壊 | AIがエラーを出さず虚偽の完了報告をする | Power Automateで実行ログをSharePointに強制書き込み。週1で人間がログを監査 |
| 暗黙の了解の欠如 | 「ファイルを消してはいけない」が通じない | 各エージェントのInstructionsに禁止事項を明示。Power Automateでファイル削除アクションを権限ブロック |
| コンテキスト混濁 | 複数エージェントが同じSharePointを書き換えて競合 | エージェントごとに書き込み先フォルダを分離（/AI-Handoff/[エージェント名]/） |
| トークンコスト爆発 | 18体が同時にGPT-4oを使い続ける | 定型処理はGPT-4o-miniに限定。Power AutomateはLLMを使わずルールベースで処理 |
